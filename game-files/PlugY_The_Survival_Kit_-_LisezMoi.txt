******** ATTENTION ********
- Ce plugin fonctionne sur LoD version 1.09 à 1.13d et 1.14d et sur leurs mods.
- PlugY4Kolbot est développé et testé uniquement sur la 1.14d. Les autres versions ne sont pas testées avec lui.
- Ce plugin ne fonctionne pas sur sur Battle.net et les autres royaumes.
- PlugY.ini a été modifié depuis les versions précédentes, utiliser celui fourni dans cette archive.
- LOD 1.14 change le répertoire de sauvegarde, vous devez donc déplacer vos fichiers de sauvegardes de PlugY manuellement.


******** CARACTERISTIQUES ********
Toutes ces fonctions peuvent être activé/désactivé via PlugY.ini (voir "COMMENTAIRES SUR LE FICHIER DE CONFIGURATION")
- Désactive l'accès à Battle.net
- Espace de stockage infini dans le coffre.
- Espace de stockage partagé dans le coffre.
- Active les mots runiques du ladder pour le monojoueur et le TCP/IP.
- World Event et Uber Quest en Local pour le monojoueur et le TCP/IP.
- Permet d'ouvrir le portail vers le Cow Level même quand on a tuer le Cow King dans cette difficulté.
- Empéche la fermeture du portail de Nihlathak.
- Déplace Deckar Cain à coté du portail d'Harrogath.
- Désalloue les points de capacités et de caractèristiques précédemment allouées.
- Crée un backup des fichiers de sauvegarde avant de sauvegarder.
- Sauvegardes protégées contre les plantages (1.14d, monojoueur, activé par défaut) : une sauvegarde qui ne modifie pas le coffre partagé est écrite en entier ou pas du tout, donc après un plantage ou un arrêt forcé, le personnage et son coffre se rechargent depuis la même sauvegarde complète.
- Change la langue du jeu.
- Régénère toujours la carte en monojoueur comme en multijoueur.
- Exécute automatiquement la comande /players X au lancement d'une partie.
- Ajoute des pages supplémentaires pour l'affichage de plus de statistiques.
- Affiche le niveau de l'objet dans son popup.
- Permet de lancer autant de fois que l'on veut Diablo II sur le même ordinateur.
- Le coffre contient 10x10 cases.
- Change le répertoire de sauvegarde.
- Affiche toujours les valeurs numériques de mana et de vie au-dessus des globes correspondants.
- D2 peut charger tout les fichiers, même ceux ouvert par Microsoft Excel (désactivé par defaut).
- Affiche la valeur courante des caractéristiques (sans les bonus magiques).
- Permet de lancer en mode fenêtré.
- Bonus de stats (1.14d, un cheat, désactivé par défaut) : ajoute du MF (chances de trouver des objets magiques) et du GF (or supplémentaire) à tous les personnages des parties que vous lancez.
- Butin de quête à chaque boss tué (1.14d, désactivé par défaut) : Andariel, Duriel, Méphisto, Diablo et Baal laissent toujours tomber leur butin de quête, même après que vous avez terminé leur quête.
- Ajout des commandes suivantes (voir "COMMENTAIRES SUR LE FICHIER DE CONFIGURATION") :
	/lockmouse : Bloque le curseur de la souris dans la fenêtre.
	/lock : Identique à /lockmouse.
	/unlockmouse : Libère le curseur de la souris de la fenêtre.
	/unlock : Identique à /unlockmouse.
	/renamepage name : Renomme la page courante du coffre (utiliser # pour le numéro de page).
	/rp name : Renomme la page courante du coffre (utiliser # pour le numéro de page).
	/setindex : La page courante devient un index.
	/setmainindex : La page courante devient un index principal.
	/resetindex : Retire la page courante des index.
	/insertpage : Insère une nouvelle page après la page courante.
	/ip : Insère une nouvelle page après la page courante.
	/deletepage : Supprime la page courante si elle est vide.
	/dp : Supprime la page courante si elle est vide.
	/swappage page : Echange le contenu de la page actuelle du coffre avec le contenu d'une autre "page".
	/sp page : Echange le contenu de la page actuelle du coffre avec le contenu d'une autre "page".
	/togglepage page : Echange le contenu de la page actuelle du coffre avec le contenu d'une autre "page" du coffre opposé partagé/personnel.
	/tp page : Echange le contenu de la page actuelle du coffre avec le contenu d'une autre "page" du coffre opposé partagé/personnel.
	/dlm : Inverse le mode d'affichage: Toujours afficher les valeurs de vie et de mana.
	/dml : Identique à /dlm.
	/dl : Identique à /dlm.
	/dm : Identique à /dlm.
	/page 1 : Affiche la page des stats de base (la page des stats doit être ouverte).
	/page 2 : Affiche la page des stats en plus (la page des stats doit être ouverte).
	/page 3 : Affiche la page des stats de resistances (la page des stats doit être ouverte).
	/page 4 : Affiche les palliers pour le joueur (la page des stats doit être ouverte).
	/page 5 : Affiche les palliers pour le mercenaire (la page des stats doit être ouverte).
	/page 6 : (beta) Affiche la page des mots runiques actifs (la page des stats doit être ouverte).
	/save : (beta) Sauvegarde la partie sans quitter.
	/listcube : (beta) Crée un fichier "cube.txt" dans le répertoire de sauvegarde contenant toutes les formules du cube.
	/renamechar newname : (beta) Renomme le personnage et le sauvegarde, en solo uniquement (2 à 15 lettres ou tirets bas).

******** INSTALLATION ********
Installation normale :
- Suivre les directives de l'installeur.
- Choisir le répertoire de Diablo II, celui qui contient Game.exe. N'importe quelle copie de Diablo II convient.
- Pour D2Bot / kolbot, cocher "Patcher Game.exe (D2Bot / kolbot)" : Game.exe démarre alors PlugY de lui-même,
  et les fichiers de PlugY vont à côté de lui. La désinstallation restaure Game.exe.

note : Avec le patch, ou avec une copie de Diablo II autre que celle que Windows a enregistrée,
tous les fichiers vont dans le répertoire de Diablo II. Sinon, vous choisissez le répertoire de
PlugY ("Mod PlugY" par défaut).

Installation silencieuse : PlugY4Kolbot_v<version>_Installer.exe /S /D2="C:\Games\Diablo II" /PATCH
installe sans afficher l'assistant, pour le répertoire de Diablo II indiqué par /D2= (un chemin complet,
entre guillemets). L'installeur se termine avec le code de sortie 2, sans rien installer, si /D2= n'est
pas un chemin complet ou si le répertoire ne contient pas Game.exe.
/PATCH coche "Patcher Game.exe (D2Bot / kolbot)" ; si Game.exe ne peut pas être patché (par exemple
pendant qu'il tourne), PlugY4Kolbot est quand même installé et l'installeur se termine avec le code de

------- D2File Patcher

PatchD2File.exe modifie Game.exe (D2gfx.dll avant la 1.14) pour qu'il lance PlugY lui-même, pour les
programmes qui lancent Game.exe directement, comme D2Bot. RestoreD2File.exe annule la modification.
- Sauvegarder D2gfx.dll ou game.exe.
- Mettre PatchD2File.exe dans le répertoire de Diablo II et l'exécuter. Quand ce répertoire en a
  besoin (par exemple sous Program Files), il demande les droits d'administrateur.
- Sans D2Bot, créer un raccourci de Game.exe : entrer le répertoire qui contient PlugY.ini dans
  "démarrer dans" de propriété->raccourci (sauf si PlugY est installé dans le répertoire de Diablo II).
- Lancer le jeu avec le raccourci !

Les options pour les scripts (-u, --dir, --silent) et les codes de sortie sont décrits dans la
section "D2File Patcher" du fichier anglais PlugY_The_Survival_Kit_-_Readme.txt.


******** MISE A JOUR ********
- En jeu : quand une version plus récente est sortie, le menu principal affiche "Update available" et la
  nouvelle version (avec ActivePrintPlugYVersion=1) ; sous 1.14d, la première partie qui la connaît affiche
  aussi une ligne dans le chat qui invite à lancer PlugY4KolbotUpdater.exe. CheckForUpdates et UpdateChannel
  dans PlugY.ini règlent la vérification.
- Fermer toutes les parties de Diablo II, puis lancer PlugY4KolbotUpdater.exe depuis le répertoire de PlugY
  (celui qui contient PlugY.exe) ; l'installeur ajoute aussi le raccourci "Check for PlugY4Kolbot updates"
  dans le menu démarrer. PlugY4KolbotUpdater.exe vérifie le téléchargement avec SHA256SUMS.txt et l'empreinte
  SHA-256 fournie par GitHub, et conserve votre PlugY.ini (l'installeur d'une préversion passe ActiveLogFile=0
  à 1 et UpdateChannel à prerelease : voir les deux plus bas), en y ajoutant les options qui lui manquent
  (voir INSTALLATION). Pour une installation faite par l'installeur, il lance le nouvel installeur pour
  cette seule installation ; sinon, il sauvegarde dans PlugY4Kolbot-backup\ chaque fichier qu'il
  remplace, ainsi que PlugY.ini avant d'y chercher les options à ajouter.
- Options pour les scripts : --check ne fait qu'informer, --yes installe sans rien demander, et --prerelease
  propose aussi les versions alpha, beta et rc (comme UpdateChannel=prerelease).
Codes de sortie : 0 mis à jour ou déjà à jour, 1 erreur, 2 mise à jour disponible (--check), 3 fichiers en
cours d'utilisation, 4 annulé.


******************** FAQ ******************

=> Je ne trouve pas le fichier PlugY.ini, où est-il ?
Dans l'explorateur Windows, aller dans outils->Options des dossiers->affichage.
Cocher "Afficher les fichiers et répertoires cachés"
Décocher "Masquer les extensions des fichiers dont le type est connu".
Le fichier PlugY.ini devrait être visible.


=> Comment jouer sur Battle.net avec PlugY installé ?
PlugY ne permet pas d'aller sur Battle.net.

=> Que faire si j'ai une erreur comme "Bad Generic File" au chargement d'un nouveau joueur ?
Ceci peut apparaître quand vous avez de mauvais objets dans le fichier du coffre partagé.
Une cause possible est l'utilisation du même répertoire de sauvegarde pour des mods différents.
Si c'est le cas, il suffit de changer ce répertoire dans PlugY.ini.
Vous pouvez aussi déplacer _LOD_SharedStashSave.sss et _LOD_HC_SharedStashSave.sss dans un autre répertoire.

=> IL y a "sUnitItemInsertItemInvGridBase failed at 1046 in C:\projects\D2\head\Diablo2\Source\D2Client\UNIT\Item.cpp" dans D2YYMMDD.txt, que dois-je faire ?
Ceci est juste un avertissement sans conséquence sur le jeu.

- Copier PlugY.ini, PlugY.exe et le répertoire PlugY dans le répertoire du mod choisi.

Chaque lancement du jeu écrit son propre log dans le dossier PlugY\logs, par exemple PlugY_2026-10-10_20-44-47_287472.log (date et heure de lancement, numéro du processus). Chaque ligne non vide commence par l'heure.

Sauvegardes protégées contre les plantages, sur la 1.14d en monojoueur uniquement.
Une sauvegarde qui ne modifie pas le coffre partagé est écrite en entier ou pas du tout : si le jeu plante ou est
arrêté à n'importe quel moment, le chargement suivant trouve soit la nouvelle sauvegarde complète, soit la
précédente complète, et le personnage (.d2s) et son fichier de coffre (.d2x) correspondent. Un arrêt ne
coûte que la progression depuis la dernière sauvegarde terminée.
Une sauvegarde qui modifie le coffre partagé écrit les fichiers de coffre (.d2x et .sss) comme avant : un arrêt
pendant cette sauvegarde peut donc encore les laisser en décalage avec le personnage ; le .d2s est quand même
toujours écrit en entier.
Activé pour les nouvelles installations comme pour les mises à jour : un PlugY.ini sans cette ligne utilise 1.
Avec 0, les sauvegardes sont écrites à l'ancienne, mais PlugY termine quand même une sauvegarde interrompue par un
plantage et refuse quand même un personnage qu'une autre partie utilise déjà.
Un arrêt au début d'une sauvegarde est annulé sans rien dire : le personnage charge sa sauvegarde précédente comme
d'habitude. Après un arrêt à la fin d'une sauvegarde (une fois celle-ci validée), le chargement suivant termine la
sauvegarde avant que le jeu ne lise le personnage : le personnage entre donc en jeu avec cette sauvegarde.
Quand le .d2s est en lecture seule ou illisible (un autre programme le garde ouvert), une sauvegarde qui ne modifie
pas le coffre partagé n'écrit ni le .d2s ni le .d2x (avec 0, le .d2x est quand même sauvegardé). Pendant la partie,
un .d2x illisible empêche aussi une telle sauvegarde.
Pendant la partie, une sauvegarde que PlugY ne peut pas faire est seulement notée dans le log, et la sauvegarde
suivante réessaie. Quand la sauvegarde faite en quittant la partie ne peut pas se faire, une boîte d'échec de
sauvegarde de PlugY par partie le signale : la progression de cette partie depuis sa dernière sauvegarde n'a pas
été sauvegardée (une boîte au sujet d'un fichier de coffre, comme un conflit du coffre partagé, peut s'y ajouter).
Si cette sauvegarde a écrit un fichier de coffre (.d2x ou .sss) mais n'a pas pu écrire le fichier du personnage, la
boîte le dit à la place : le personnage et son coffre peuvent alors ne pas correspondre jusqu'à la prochaine
sauvegarde réussie.
Quand le fichier du personnage est un .d2s en lecture seule, cette boîte ("its character file ... is read-only") ne
s'affiche qu'une fois par personnage jusqu'à la fermeture de Diablo II : un personnage gardé exprès en lecture
seule ne provoque donc pas une boîte à chaque partie. Retirez l'attribut lecture seule pour sauvegarder à nouveau ce
personnage. Les autres échecs (un .d2s illisible, un fichier verrouillé, un disque plein) affichent une boîte à
chaque partie où ils se produisent.
Quand PlugY refuse de charger un personnage, une boîte de dialogue indique pourquoi et quoi faire, par exemple :
- "already running in another game" : fermez l'autre partie, puis chargez à nouveau le personnage. Le chargement
  attend d'abord jusqu'à 5 secondes environ que l'autre partie libère le personnage.
- "can't be read" : fermez le programme qui garde ce fichier ouvert, ou corrigez ses permissions. Un fichier qu'un
  autre programme garde ouvert un instant ne refuse le chargement qu'une fois, sans boîte ; la boîte s'affiche si
  cela arrive deux fois de suite.
- "finishing its interrupted save needs to change <file>, which failed" : ce fichier est en lecture seule,
  verrouillé par un autre programme, ou le disque est plein. Corrigez-le, puis chargez à nouveau le personnage.
- "its stash file ... carries a save mark, but no save journal is left to finish that save" : le .d2x contient
  encore le coffre de la dernière sauvegarde terminée du personnage. La marque de sauvegarde est le "0J" juste après
  "CSTM" au début du fichier (un .d2x normal a "01" à cet endroit) : restaurez le .d2x depuis un backup, ou remettez
  "01" à la place de ce "0J" avec un éditeur hexadécimal. Un .d2x de seulement 6 octets ne contient aucun coffre :
  supprimez-le plutôt. Dans tous les cas, le coffre est celui d'avant la sauvegarde interrompue ; si le fichier du
  personnage est plus récent, les objets déplacés entre le personnage et son coffre depuis cette sauvegarde peuvent
  être en double ou manquer.
- "its save journal ... can't be read back" : ne supprimez ce .pyj que si vous acceptez de perdre la sauvegarde
  qu'il contient. Si la boîte dit aussi que le fichier de coffre "carries a save mark", retirez également cette
  marque, comme l'indique le point ci-dessus.
- "the character files match neither side of the save in its journal" : restaurez le personnage depuis un backup,
  ou ne supprimez le .pyj que si vous acceptez de perdre la sauvegarde qu'il contient. Si la boîte dit aussi que le
  fichier de coffre "carries a save mark", retirez également cette marque, comme l'indique le point
  "carries a save mark" plus haut.
Ces boîtes de dialogue suivent ShowErrorMessageBox (voir [GENERAL]).
PlugY garde deux fichiers par personnage à côté des sauvegardes :
- <nom>.pyj, le journal d'une sauvegarde en cours. Il ne reste que pendant une sauvegarde, ou jusqu'à ce qu'un
  fichier qu'il doit remplacer puisse être écrit (PlugY réessaie environ toutes les 2 secondes pendant la partie, et
  à la sauvegarde ou au chargement suivant du personnage) ; celui qu'un plantage a laissé est terminé ou annulé au
  chargement ou à la sauvegarde suivante du personnage. Tant qu'il existe, les versions plus anciennes de PlugY
  peuvent refuser de charger le personnage au lieu de charger une moitié de sauvegarde.
  Quand un personnage a été supprimé puis recréé sous le même nom, son ancien .pyj est renommé en
  <nom>.pyj.orphan-<YYYYMMDD-HHMMSS> et son .d2x restant, s'il existe, en <nom>.d2x.orphan-<YYYYMMDD-HHMMSS>, pour
  que le nouveau personnage reparte de zéro ; quand seuls ses fichiers ont été remplacés par d'autres, seul le .pyj
  est renommé.
- <nom>.pylive, le verrou du personnage en cours de jeu : tant qu'une partie utilise un personnage, aucune autre
  partie ne peut le charger ni le sauvegarder. Le verrou prend fin avec la partie : dès qu'un Game.exe est revenu au
  menu, une autre partie peut charger le personnage ; un chargement du personnage qui échoue, parce que PlugY le

[STAT BONUS]
ATTENTION : CHEAT, NE PAS UTILISER EN PARTIE NORMAL.
Donne à vos personnages un bonus de MF (chances de trouver des objets magiques) et de GF (or supplémentaire) qui s'ajoute au MF et au GF de leur équipement (1.14d uniquement).
Ce bonus fonctionne comme le MF et le GF des objets ; le MF garde ses rendements décroissants habituels pour les objets uniques, de set et rares.
Le serveur de jeu l'ajoute chaque fois qu'un personnage entre dans une partie : en monojoueur, et pour chaque personnage d'une partie TCP/IP que vous hébergez (les valeurs MagicFind et GoldFind propres à un joueur qui rejoint la partie n'ont aucun effet). Le bonus n'est jamais sauvegardé dans le fichier du personnage : avec des fichiers de données qui sauvegardent le MF ou le GF (certains mods), le bonus correspondant n'est pas appliqué.
La page de stats supplémentaire de PlugY (/page 2, avec ActiveNewStatsInterface=1) affiche le total. Dans une partie TCP/IP, un joueur qui rejoint la partie le voit sur cette page s'il utilise cette version de PlugY4Kolbot avec ActiveMultiPageStash=1 ou ActiveStatBonus=1.
Ci-dessous, les valeurs par défauts et entre {} des exemples avec leurs significations :
- ActiveStatBonus=0		{0:Désactivé; 1:Activé}
- MagicFind=0			{0:aucun bonus; 999:999% de MF en plus; maximum 10000}
- GoldFind=0			{0:aucun bonus; 200:200% de GF en plus; maximum 10000}
